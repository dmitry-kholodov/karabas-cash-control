# Архитектура KARABAS Cash Control

KARABAS построен как модульный pipeline автоматизации документооборота.

Основная идея — отделить получение документов от их обработки и от конкретной бизнес-системы, куда в итоге должны попасть данные.

## Основной pipeline

Документ / фотография / скан  
↓  
AI Document Understanding  
↓  
Structured JSON  
↓  
Pydantic Validation  
↓  
Business Classification  
↓  
Python Processing  
↓  
Integration Layer  
↓  
Excel / другое хранилище

## 1. Входные данные

В текущей реализации поддерживается загрузка изображений.

Архитектура допускает подключение дополнительных источников:

- PDF;
- текстовые документы;
- Telegram;
- web-interface;
- корпоративные файловые хранилища.

## 2. AI Document Understanding

Документ передаётся в AI-модель через API.

Модель извлекает необходимые бизнес-данные и возвращает их в структурированном формате.

Для кассовых отчётов это могут быть:

- дата;
- наличная выручка;
- безналичная выручка;
- расходы;
- категория расхода;
- комментарий.

## 3. Structured Data

Ответ модели преобразуется в JSON.

Использование строгой структуры позволяет отделить AI-распознавание от последующей бизнес-логики.

## 4. Validation Layer

Pydantic используется для проверки структуры и типов данных.

Это снижает вероятность передачи некорректного AI-ответа в следующий этап системы.

## 5. Business Classification

После распознавания данные могут проходить дополнительную классификацию по правилам конкретного бизнеса.

Категории и правила могут отличаться для каждого заказчика.

## 6. Integration Layer

Обработанные данные передаются в целевую систему.

Текущий сценарий — Excel через OpenPyXL.

Архитектура позволяет подключать:

- Excel;
- Google Sheets;
- базы данных;
- ERP / CRM;
- внутренние аналитические системы.

## Приватная часть

Публичный репозиторий содержит только демонстрацию архитектуры.

Не публикуются:

- production prompts;
- реальные бизнес-категории;
- клиентские данные;
- точный Excel mapping;
- правила обработки конкретного бизнеса;
- production-конфигурация.

Это позволяет показать технический подход проекта без публикации внутренней бизнес-логики.
